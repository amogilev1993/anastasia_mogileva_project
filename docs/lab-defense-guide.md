## 1. Создать не менее двух пользователей (2 балла)

### Команды
```bash
# Создаём пользователя с домашним каталогом и оболочкой bash
sudo useradd -m -s /bin/bash anna
sudo useradd -m -s /bin/bash boris

# Задаём им пароли (без этого аккаунт заблокирован для входа по паролю)
sudo passwd anna
sudo passwd boris
```
Флаги `useradd`:
- `-m` — создать домашний каталог `/home/anna` (скопировать туда содержимое `/etc/skel`);
- `-s /bin/bash` — задать командную оболочку (login shell);
- `-c "Anna Ivanova"` — комментарий (GECOS, полное имя), необязательно;
- `-u 1010` — задать конкретный UID (необязательно).

> ⚠️ В Debian/Ubuntu есть удобный интерактивный скрипт `sudo adduser anna` — он сам создаёт каталог, спрашивает пароль и т.д. На защите можно показать любой; `useradd` — «низкоуровневый», `adduser` — обёртка. Знай оба.

### Что показать комиссии
```bash
grep -E 'anna|boris' /etc/passwd
sudo grep -E 'anna|boris' /etc/shadow
id anna
```

### Разбор полей `/etc/passwd` (7 полей через `:`)
Пример строки: `anna:x:1001:1001:Anna Ivanova:/home/anna:/bin/bash`

| № | Поле | Значение |
|---|------|----------|
| 1 | `anna` | **имя пользователя** (login) |
| 2 | `x` | **пароль**: `x` означает «хэш лежит в `/etc/shadow`» |
| 3 | `1001` | **UID** — числовой идентификатор пользователя (0 = root, 1–999 системные, ≥1000 обычные) |
| 4 | `1001` | **GID** — идентификатор основной (первичной) группы |
| 5 | `Anna Ivanova` | **GECOS** — комментарий/полное имя, телефон и т.п. |
| 6 | `/home/anna` | **домашний каталог** |
| 7 | `/bin/bash` | **оболочка входа**; `/usr/sbin/nologin` или `/bin/false` запрещают вход |

### Разбор полей `/etc/shadow` (9 полей через `:`)
Пример: `anna:$y$j9T$...хэш...:19876:0:99999:7:::`

| № | Поле | Значение |
|---|------|----------|
| 1 | `anna` | имя пользователя |
| 2 | `$y$...` | **хэш пароля**. Префикс = алгоритм: `$y$`/`$7$` = yescrypt (по умолчанию в новых Ubuntu), `$6$` = SHA-512. `!` или `*` = вход по паролю заблокирован, пустое = пароль не задан |
| 3 | `19876` | дата последней смены пароля (в днях с 01.01.1970) |
| 4 | `0` | **min** — минимум дней между сменами пароля |
| 5 | `99999` | **max** — максимум дней действия пароля |
| 6 | `7` | **warn** — за сколько дней предупреждать об истечении |
| 7 | (пусто) | **inactive** — сколько дней после истечения аккаунт ещё активен |
| 8 | (пусто) | **expire** — дата окончательной блокировки аккаунта |
| 9 | (пусто) | зарезервировано |

## 2. Политика паролей для одного пользователя (2 балла)

Управляет сроком действия пароля утилита `chage` (CHange AGE). Она меняет поля 4–8 в `/etc/shadow`.

### Команды
```bash
# Посмотреть текущую политику
sudo chage -l anna

# Настроить политику:
sudo chage -m 7 -M 90 -W 14 -I 30 anna
#   -m 7  : минимум 7 дней между сменами пароля
#   -M 90 : пароль действует максимум 90 дней
#   -W 14 : предупреждать за 14 дней до истечения
#   -I 30 : через 30 дней после истечения аккаунт деактивируется

# Задать дату окончательной блокировки аккаунта:
sudo chage -E 2026-12-31 anna

# Заставить сменить пароль при следующем входе:
sudo chage -d 0 anna
```

### Что показать и рассказать
```bash
sudo grep anna /etc/shadow      # увидишь изменившиеся поля 4-8
sudo chage -l anna              # человекочитаемый вид
```
Объясни: «поле 4 (min) стало 7, поле 5 (max) — 90, поле 6 (warn) — 14, поле 7 (inactive) — 30». Свяжи поля shadow с тем, что задали через `chage`.

> Бонус (если спросят про сложность/длину пароля): за это отвечает PAM-модуль `pam_pwquality` (файл `/etc/security/pwquality.conf`, параметры `minlen`, `dcredit`, `ucredit` и т.д.), а `chage` — только про сроки. Не путай «политику сроков» и «политику сложности».

<a name="3"></a>
## 3. Сменить пароль (1 балл)

```bash
# Root меняет пароль пользователю (пароль не нужен знать):
sudo passwd anna

# Пользователь сам меняет свой пароль (спросит старый):
passwd
```
Разница: `passwd` без аргумента меняет твой собственный пароль и требует ввести текущий; `sudo passwd anna` меняет чужой и текущий не спрашивает. Под капотом обновляется хэш в поле 2 файла `/etc/shadow` и дата смены (поле 3).

<a name="4"></a>
## 4. Группы и их состав (2 балла)

### Команды
```bash
# Создаём две группы
sudo groupadd developers
sudo groupadd testers

# Добавляем пользователей в группы (-a = добавить, -G = доп.группа; БЕЗ -a сотрёт остальные!)
sudo usermod -aG developers anna
sudo usermod -aG developers boris
sudo usermod -aG testers anna
sudo usermod -aG testers boris

# Альтернатива — gpasswd:
sudo gpasswd -a anna developers
```
⚠️ **Запомни намертво:** `usermod -G` без `-a` **заменяет** список дополнительных групп. Всегда `-aG`.

### Что показать
```bash
grep -E 'developers|testers' /etc/group
id anna
groups boris
getent group developers
```

### Разбор полей `/etc/group` (4 поля через `:`)
Пример: `developers:x:1005:anna,boris`

| № | Поле | Значение |
|---|------|----------|
| 1 | `developers` | имя группы |
| 2 | `x` | пароль группы (`x` → в `/etc/gshadow`, обычно не используется) |
| 3 | `1005` | **GID** группы |
| 4 | `anna,boris` | **список членов** (это дополнительная/вторичная группа для них) |

> Важный нюанс: **основная (первичная) группа** пользователя задаётся в `/etc/passwd` (поле 4) и в `/etc/group` в 4-м поле может НЕ отображаться. То есть если у anna первичная группа `anna`, она в списке членов своей группы не пишется, но `id anna` её покажет. Будь готова это объяснить.

<a name="5"></a>
## 5. Работа от другого пользователя: su и sudo (2 балла)

### su (substitute user)
```bash
su - anna        # полностью переключиться на anna (спросит ПАРОЛЬ anna), - = login shell
whoami           # покажет anna
exit             # вернуться обратно

sudo su -        # стать root (спросит ТВОЙ пароль через sudo)
su -             # стать root напрямую (спросит пароль root; в Ubuntu root по умолчанию заблокирован!)
```
- `su - anna` — запускает login-оболочку anna (читает её профиль, меняет каталог на /home/anna, окружение). Без `-` сохраняется текущее окружение и каталог.
- В Ubuntu учётка root по умолчанию заблокирована (`!` в shadow), поэтому `su -` без sudo не сработает, пока не задашь пароль root через `sudo passwd root`.

### sudo (superuser do)
```bash
sudo команда              # выполнить ОДНУ команду с правами root, вводя СВОЙ пароль
sudo -u boris команда     # выполнить команду от имени boris
sudo -i                   # интерактивная root-сессия
sudo -l                   # показать, что тебе разрешено
```
Кто имеет право на sudo — задаётся в `/etc/sudoers` (редактировать ТОЛЬКО через `sudo visudo`, он проверяет синтаксис) и в `/etc/sudoers.d/`. В Ubuntu право даёт членство в группе `sudo`:
```bash
sudo usermod -aG sudo anna     # дать anna права sudo
```
Строка в sudoers: `%sudo  ALL=(ALL:ALL) ALL` — «члены группы sudo могут выполнять любые команды от любого пользователя».

### Разница su vs sudo (главный вопрос)
| | su | sudo |
|---|----|----|
| Какой пароль | пароль ЦЕЛЕВОГО пользователя | СВОЙ пароль |
| Сколько команд | открывает целую сессию | по одной команде (по умолчанию) |
| Логирование | меньше | каждая команда логируется (`/var/log/auth.log`) |
| Гранулярность прав | всё или ничего | можно разрешить только конкретные команды |

<a name="6"></a>
## 6. Удалить пользователя (0.5 балла)
```bash
sudo userdel boris            # удалить пользователя, но ОСТАВИТЬ /home/boris
sudo userdel -r boris         # удалить вместе с домашним каталогом и почтой
```
Проверка: `grep boris /etc/passwd` → строки больше нет.
`-r` (remove) удаляет `/home/boris` и `/var/mail/boris`. Объясни, что без `-r` файлы остаются «осиротевшими» (числятся за бывшим UID).

## 7. Удалить группу (0.5 балла)
```bash
sudo groupdel testers
```
Проверка: `grep testers /etc/group` → пусто.
Нюанс: нельзя удалить группу, если она является **первичной** для какого-то пользователя — сначала смени ему первичную группу. Дополнительную группу удалить можно всегда.

<a name="8"></a>
## 8. Права доступа: абсолютный и относительный режим (2 балла)

### Подготовка
```bash
mkdir -p ~/lab && cd ~/lab
touch file.txt
ls -l file.txt        # смотрим текущие права
```
Читаем вывод `-rw-r--r--`:
- 1-й символ — тип: `-` файл, `d` каталог, `l` ссылка;
- далее 3 триады по 3 бита: **владелец (u)**, **группа (g)**, **остальные (o)**;
- `r`=4 (чтение), `w`=2 (запись), `x`=1 (выполнение/вход в каталог).

### Абсолютный (числовой/восьмеричный) режим
Каждая триада — сумма: rwx=7, rw-=6, r-x=5, r--=4.
```bash
chmod 750 file.txt    # u=rwx(7) g=r-x(5) o=---(0)
ls -l file.txt        # -rwxr-x---
chmod 644 file.txt    # u=rw- g=r-- o=r--
```

### Относительный (символьный) режим
Синтаксис: `[ugoa][+-=][rwx]`.
```bash
chmod u+x file.txt    # добавить владельцу право выполнения
chmod g-w file.txt    # убрать у группы запись
chmod o=r file.txt    # выставить остальным ровно r--
chmod a+r file.txt    # всем (a=all) добавить чтение
chmod g+w,o-r file.txt # несколько изменений сразу
```
Объясни разницу: **абсолютный** задаёт права целиком (перезаписывает), **относительный** добавляет/убирает отдельные биты относительно текущих. Покажи `ls -l` до и после каждого изменения.

Смена владельца/группы (часто спрашивают рядом):
```bash
sudo chown anna file.txt          # сменить владельца
sudo chown anna:developers file.txt   # владелец + группа
sudo chgrp developers file.txt    # только группа
chmod -R 755 ~/lab                # -R рекурсивно для каталога
```

<a name="9"></a>
## 9. Специальные атрибуты: SUID, SGID, sticky (2 балла)

Это 4-я (старшая) восьмеричная цифра в правах: **SUID=4, SGID=2, sticky=1**.

### SUID (Set User ID) — 4xxx
Файл-программа выполняется с правами ВЛАДЕЛЬЦА файла, а не запустившего.
```bash
ls -l /usr/bin/passwd        # -rwsr-xr-x  ← 's' в триаде владельца = SUID
```
Почему `passwd` имеет SUID: обычному пользователю надо записать в `/etc/shadow` (владелец root), поэтому при запуске passwd получает права root. Это лучший живой пример для защиты.
```bash
sudo chmod u+s myprog        # или: sudo chmod 4755 myprog
```
В выводе `ls -l` SUID = буква `s` на месте `x` у владельца (`rws`). Если `x` не было — будет заглавная `S`.

### SGID (Set Group ID) — 2xxx
- На **файле**: выполняется с правами группы-владельца.
- На **каталоге** (самое полезное): новые файлы внутри наследуют ГРУППУ каталога, а не первичную группу создателя. Идеально для общих папок команды.
```bash
sudo mkdir /srv/shared
sudo chgrp developers /srv/shared
sudo chmod 2775 /srv/shared      # 2 = SGID
ls -ld /srv/shared               # drwxrwsr-x  ← 's' в триаде группы
# Демонстрация: создаём файл и видим, что группа = developers
sudo -u anna touch /srv/shared/test
ls -l /srv/shared/test           # группа будет developers, а не anna
```

### Sticky bit — 1xxx
На каталоге: удалять/переименовывать файл может только его владелец (или root), даже если у других есть запись. Классика — `/tmp`.
```bash
ls -ld /tmp                  # drwxrwxrwt  ← 't' на месте x у "остальных"
sudo chmod +t /srv/shared    # или chmod 1775
ls -ld /srv/shared           # ...rwt в конце
```
В `ls -l`: sticky = `t` в позиции `x` у «остальных» (`rwt`). Заглавная `T`, если `x` не было.

> Выбери для защиты один атрибут и продемонстрируй полностью с эффектом (рекомендую SGID на каталоге или sticky на /tmp — нагляднее всего). Но знать назначение всех трёх.

<a name="10"></a>
## 10. umask — права по умолчанию + разница (2 балла)

`umask` — маска, которая **вычитает** биты из базовых прав при создании объектов.
Базовые права: **файлы 666** (rw для всех), **каталоги 777**. Реальные = базовые & (NOT umask).

### Демонстрация «до — меняем — после»
```bash
umask                       # показать текущую маску (обычно 0022)

# СТАРЫЕ настройки (umask 022):
touch old_file
mkdir old_dir
ls -l old_file              # -rw-r--r--  (666 - 022 = 644)
ls -ld old_dir              # drwxr-xr-x  (777 - 022 = 755)

# Меняем маску:
umask 077                   # теперь всё приватно

# НОВЫЕ настройки:
touch new_file
mkdir new_dir
ls -l new_file              # -rw-------  (666 - 077 = 600)
ls -ld new_dir              # drwx------  (777 - 077 = 700)
```
Объясни арифметику на пальцах: `umask 022` → у группы и остальных убирается бит `w`(2). `umask 077` → у группы и остальных убираются все биты. Файлы не получают `x` по умолчанию, даже если маска позволяет (это защита: данные не должны быть исполняемыми).

Постоянно (между перезагрузками) umask задаётся в `~/.bashrc` (для пользователя) или `/etc/profile`, `/etc/login.defs` (системно). Для демонстрации достаточно временно в текущей сессии.

<a name="11"></a>
## 11. Система аудита — auditd (2 балла)

`auditd` (Linux Audit Daemon) фиксирует события безопасности на уровне ядра: доступ к файлам, вызовы, изменения.

### Установка и запуск
```bash
sudo apt update
sudo apt install auditd audispd-plugins -y
sudo systemctl enable --now auditd
sudo systemctl status auditd        # должно быть active (running)
```

### Настройка правила (две типовые демонстрации)

**Вариант А — следить за изменением файла (watch):**
```bash
# -w путь  -p права(w=запись,a=атрибуты,r=чтение,x=выполнение)  -k метка
sudo auditctl -w /etc/passwd -p wa -k passwd_changes
sudo auditctl -l                    # показать активные правила
```
Спровоцировать событие и посмотреть:
```bash
sudo useradd testaudit              # это изменит /etc/passwd
sudo ausearch -k passwd_changes     # найти события по метке
# или
sudo ausearch -k passwd_changes | tail -20
```

**Вариант Б — следить за каталогом/командой:**
```bash
sudo auditctl -w /etc/shadow -p wa -k shadow_watch
sudo auditctl -w /srv/shared -p rwxa -k shared_access
```

### Постоянные правила
Временные правила (`auditctl`) исчезают после перезагрузки. Постоянные пишут в `/etc/audit/rules.d/audit.rules`, затем:
```bash
echo '-w /etc/passwd -p wa -k passwd_changes' | sudo tee -a /etc/audit/rules.d/audit.rules
sudo augenrules --load        # применить
sudo systemctl restart auditd
```

### Чтение результатов
```bash
sudo ausearch -k passwd_changes          # поиск по метке (key)
sudo ausearch -f /etc/passwd             # поиск по файлу
sudo ausearch -ui 1001                   # по UID пользователя
sudo aureport                            # сводный отчёт
sudo aureport -f                         # отчёт по доступу к файлам
```
Лог-файл: `/var/log/audit/audit.log`. Конфиг демона: `/etc/audit/auditd.conf` (где хранить логи, ротация, размер).

### Что объяснить комиссии
- `auditctl` — управление правилами (добавить/показать/удалить);
- `-w` watch (файл/каталог), `-p` permissions (r/w/x/a), `-k` key (метка для поиска);
- `ausearch` ищет события, `aureport` строит отчёты;
- разница между временными (auditctl) и постоянными (rules.d + augenrules) правилами;
- покажи: правило → действие (изменил файл) → событие в логе через `ausearch`.

> Задание разрешает настроить заранее. Сделай правило и спровоцируй событие ДО защиты, чтобы в логе уже было что показать; на защите объясни настройку и покажи `ausearch`.

<a name="faq"></a>
## 12. Частые вопросы на защите (и краткие ответы)

- **Чем `useradd` отличается от `adduser`?** `useradd` — низкоуровневая утилита; `adduser` — дружелюбный Perl-скрипт-обёртка (Debian/Ubuntu), создаёт каталог, спрашивает пароль интерактивно.
- **Где хранятся пароли и почему два файла?** Хэши — в `/etc/shadow` (доступен только root), а `/etc/passwd` читаем всеми. Раньше хэши были в passwd — это было небезопасно.
- **Что такое UID 0?** Это root. Любой пользователь с UID 0 = суперпользователь.
- **Граница системных и обычных пользователей?** Обычно UID ≥ 1000 — люди, < 1000 — системные (задаётся в `/etc/login.defs`, `UID_MIN`).
- **Что значит `x` в `/etc/passwd`?** Что хэш пароля вынесен в shadow.
- **Зачем нужен sticky bit на `/tmp`?** Чтобы пользователи не удаляли чужие файлы в общедоступном для записи каталоге.
- **Разница абсолютного и относительного chmod?** Абсолютный (644) перезаписывает все биты; относительный (u+x) меняет отдельные биты.
- **Почему файл при umask не получает x?** Базовое право файлов = 666 (без x намеренно), поэтому исполнять по умолчанию нельзя.
- **su vs sudo?** см. таблицу в п.5: разный пароль, гранулярность, логирование.
- **Первичная vs дополнительная группа?** Первичная — в `/etc/passwd` (поле GID), применяется к новым файлам пользователя; дополнительные — в `/etc/group`, дают доступ к ресурсам групп.

## Рекомендуемый порядок действий на защите (сценарий «прогона»)
1. `sudo useradd -m -s /bin/bash anna` + `boris`, `passwd` обоим → показать `/etc/passwd`, `/etc/shadow`, разобрать поля.
2. `sudo chage -M 90 -m 7 -W 14 anna` → `chage -l anna` + поля shadow.
3. `sudo passwd anna` → смена пароля.
4. `groupadd developers/testers`, `usermod -aG ...` → `/etc/group`, `id`.
5. `su - anna`, `sudo -u boris ...`, `sudo -l` → разница.
6. `userdel -r boris`.
7. `groupdel testers`.
8. `chmod 750` / `chmod u+x` на `~/lab/file.txt` → `ls -l` до/после.
9. SGID на `/srv/shared` (или sticky на демо-каталоге) → создать файл, показать наследование/защиту.
10. `umask 022` → создать объекты → `umask 077` → создать → сравнить `ls -l`.
11. `auditctl -w /etc/passwd -p wa -k passwd_changes` → спровоцировать → `ausearch -k passwd_changes`.

Удачи на защите! Главное — не просто вводить команды, а **проговаривать что и зачем**, и читать вывод `ls -l` / конфигов по полям.
